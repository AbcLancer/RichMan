# RichMan6 Replica —— 大富翁6 即时制复刻

复刻经典游戏《大富翁6》（软星 Softstar, 2002），**重点是即时制玩法**，并重做联机功能。

- **素材**：复用原版本体资源（`F:\游戏\Rich6\gamedata.pck`，已完整解包）
- **引擎**：Godot 4.x + GDScript
- **联机**：权威服务端架构（房主即服务端），后续扩展为独立大厅
- **美术**：P0 用程序化占位，P3 阶段做画面升级

> ⭐ **对齐度全面体检** → **`docs/alignment-gap.md`**（2026-09-26）：原版还有哪些功能我们没做、
> 每条的原始证据（配置行 / 素材目录 / 消息号）、建议优先级。**「还有哪里不对」先看这份。**
>
> 定点逆向工具 → **`tools/r6_re.py`**：原版没有脚本也没有符号（详见 `docs/alignment-gap.md §0`），
> 但可以拿字符串/常量地址反查「哪段代码用了它」。用法见 `docs/decision-log.md §15.2`。

## 怎么打开

### 方式一：双击 `PLAY.bat`（推荐）

在工程根目录双击 **`PLAY.bat`** 即可。它会自动按以下顺序找 Godot，找到哪个用哪个：

1. `D:\Godot\Godot_v4.7.2-stable_win64.exe` ← 当前用的
2. `.\Godot\`（放在工程里也行）
3. `.\.tools\`
4. `%LOCALAPPDATA%\Microsoft\WinGet\Packages\...`

窗口分辨率 1440×810。四个位置都没有时会提示，并告诉你放哪里。

> ⚠️ **别敲 `godot` 命令** —— winget 非管理员安装建不出符号链接，
> `%LOCALAPPDATA%\Microsoft\WinGet\Links\godot.exe` 是个 0 字节空文件，
> 敲下去**不报错也不启动**，很容易误判成 Godot 坏了。

### 方式二：Godot 编辑器

打开 Godot 4.7.2 → 「导入」→ 选择 `D:\Projects\RichMan\game\project.godot` → 打开后按 **F5**。
（推荐后续做画面调试时用这个。）

### 进去之后怎么玩

1. 主菜单填昵称 → 选地图 → 点 **▶ 单人练习（对阵 3 名电脑）** —— 立刻开局，无需配置
2. 想联机：一方点 **创建房间（主机）**，记下显示的局域网 IP；
   另一方填该 IP 点 **加入房间**；房主点 **开始游戏**
3. 对局中：**空格**或点角色头顶的 **GO 圆钮**前进。
   GO 钮**左侧竖排两颗骰子 = 掷骰颗数选择器**（白=选中 / 灰=没选，点一下切换，上下限就是 1~2 颗
   —— 原版实机 5 张截图一致只有 2 颗，见 `docs/ui-audit.md §5c`）。
   掷出后骰子会从 GO 钮**飞到角色头顶翻转**，停住时显示点数。
4. 走到空地亮起「购买地产」；**走到自己的地**才亮起「升级地产」
   （一次抵达只给一次机会，想连升要么走开再回来、要么用停留卡 / 升级卡）；
   不想买不想升就点「跳过」，否则人站在格子上会一直攥着这次机会
5. **卡片**：走到「卡片点 / 卡片商店」会拿到卡 → 屏幕**底部手牌条**会出现卡面 →
   **点卡片**弹出 **使用 / 锁定 / 丢弃**（原版 `String.txt` id 1/2/3）→
   需要点对手的卡（穷神 / 衰神 / 查税 / 抢夺 / 均富 / 诱拐）会提示 **请选择对手**，
   这时**点右侧玩家头像**即用。**Q** 或左下角「卡片夹」按钮可以收起手牌条。
   > 卡片的**界面版式**是重建的（原版版式查不到证据），但**文案 100% 取原版 `String.txt`**；
   > 42 张卡里 **39 张已实现**，红卡/黑卡/复制卡因股票与卡片组合子系统未做会提示「暂不可用」
   > 且**不消耗卡片**。详见 `docs/ui-audit.md §11/§12`。
6. 左下角是角色面板（**左细条 = 体力**，每走 1 格 -20、每秒 +7，低于 240 不让出发）；
   右下角是原版小地图。事件日志用 **L / C** 开合。

```bash
PY=".workbuddy/venv/Scripts/python.exe"          # 需 numpy/pillow/scipy（本工程 venv）
$PY tools/r6_unpack_logic.py                     # 160 文本 → UTF-8；117 二进制 → *.dump.txt

$PY tools/red_boxes_to_tilepos.py                # 50 个红框 → 校准步距/格数（候选）
$PY tools/walkway_mask.py [--tex ditu|ditu_noshadow|ditu2_1024]
                                                 # 步道掩码 + 中心线 + 逐格对齐度量
                                                 # ⚠️ 量「我们棋盘对不对得上」必须用默认的 ditu
$PY tools/route_from_walkway.py [--n 94]         # 沿步道中心线重建棋盘格点（94 格）+ 验收叠图
$PY tools/check_minimap_uv.py                    # 判定小地图 UV 方向（左右环高度序等硬判据）
$PY tools/minimap_route.py                       # 从原版小地图提取路线拓扑（另存 JSON）
```

- `docs/orig-logic/INDEX.md` 全量索引，`refs.md` 跨文件引用（音效 id / 源文件 / 开发机路径），
  **`FINDINGS.md` 是人工整理的结论**（原版《地图制作的要求》、相机 45/20/1000、
  33 条场景动画→音效映射、新闻画面像素矩形 …）。
- `docs/orig-scene/INDEX.md`：8 张图的街区划分（埃及 20 个街区、ΣA = 94 格）与坐标，
  来自 `.r6s` 里的 `R6_Route_1` / `R6_Bblock_AxB_i` 节点。
- **`.r6m` 地产块表**（`offset 504` 起，记录长 `48×A+76`）已解，与 `.r6s` 交叉验证一致。
- **对齐结论**：111 格到 `ditu.tga` 步道的距离 **中位 6.9 px**（整体贴合良好）；
  红框步距 29.98 px 提示原版约 **92~94 格**（我们现在 111 格偏密）。
  详见 `docs/original-visual-reference.md` 附录 B/C 与 `docs/decision-log.md` §十。

## 架构

```
      客户端 A                房主（= 权威服务端）              客户端 B
   ┌──────────┐            ┌───────────────────┐            ┌──────────┐
   │ 输入采集 │            │   Sim.step(dt)    │            │ 输入采集 │
   │ 状态渲染 │  ──意图──▶ │  20 Hz 逻辑帧      │ ◀──意图── │ 状态渲染 │
   │ 插值显示 │  ◀─快照──  │  10 Hz 状态广播    │  ──快照──▶ │ 插值显示 │
   └──────────┘            └───────────────────┘            └──────────┘
```

**关键设计**：`Sim` 类**不含任何渲染与网络代码**，因此在服务端和客户端行为完全一致。
换传输层（P2 → 独立大厅/专用服务器）时只需替换 `net.gd`，玩法逻辑零改动。

### 已知问题

- **建筑贴图仍不完美（议题 20，2026-09-25 更新）**：字段语义已定死 ——

  实测 `f4` 只随 (x,z)、`f5` 只随 y → 是 **UVW Map「盒投影」**（模型名 `Box02`），
  而原版图集是一张「房子壁纸」（草皮/白墙/窗门/屋顶分区）→ 每面**取错了一块**。
  **已排除**：u/v 翻转或交换、`.max` 有 UV、材质块有第二套 UV、索引块扫错、
  打包 `snap_uv_to_content/bleed_atlas` 破坏贴图（`tools/bld_sheet.py` 对照表证明两列一致）。
  逐栋核对：`--probe=<type>:<level>`。

- **大建筑会互相穿插**：地毯间距只有 1 格，而 3×3 建筑跨 3.24 格 → 相邻两格都盖满级必然穿插。
  原版靠**占地预订**（吃掉邻格、禁别人盖）避免，我们**没实现**（老板未拍板）。
  展示模式已用 stride=3 规避，**玩法侧仍待决策**。
- **只有埃及（aiji）有 `ditu*` 俯视棋盘美术**，其余 7 张地图走兜底布局
  （纯色沙地 + 程序生成矩形地毯环，小地图不叠加）。见 `docs/decision-log.md` 议题 2。
- **棋盘坐标是「重建」不是「还原」**（2026-09-25 更新）：`.r6m` 头部（雾色 / 太阳方向 /
  镜头角 / 街道名表）已逐字段解出；`offset 504` 起的**地产块表也已解出**（记录长 `48×A+76`），
