## 0. 度量口径（先看这个，否则后面所有数字都对不上）

| 项 | 值 |
|----|----|
| 原版设计分辨率 | **1024 × 768**（4:3） |
| 原版实机截图 | `docs/screenshots/orig/07_牌桌.png` = **1536 × 1152 = 设计像素 × 1.5** |
| 我们的渲染 | 1280 × 720（16:9） |
| 缩放因子 | `UI_SCALE = 视口高 / 768`（720p 下 = **0.9375**） |
| 换算 | 截图 px → native：**÷1.5**；native → 屏幕 px：**× UI_SCALE** |

⚠️ 因为原版是 4:3、我们是 16:9，**同一个 `UI_SCALE` 会让 HUD 元素在更宽的屏上占屏比更小**
（例：左下角色面板宽 220/1024 = 21.5% vs 206/1280 = 16.1%）。这是**正确行为**——
元素自身长宽比不变，只是横向留白更多。**不要为了"占屏比一致"去单独拉伸宽度。**

⚠️ 「native」= 原版 1024×768 设计像素，**不是屏幕像素**。3D 世界里角色在屏上多大
取决于相机距离与投影，跟 native 无关 —— 见 §6 的抬升量说明。

### 5a. ⭐ GO 钮是**两张贴图叠出来的**（2026-09-25 纠正）

**单独用任一张都不对** —— 两张都是「贴边裁切」的残图：

| 素材 | 尺寸 | 可见区 alpha bbox | 说明 |
|------|------|------------------|------|
| `labar/背景.png` | 64×64 | `(0, 3, 64, 64)` | 深蓝球（左右贴边 → 直径就是 64） |
| `labar/go.png` / `go_dn.png` | 64×64 | `(0, 10, 41, 64)` | 青球 + 「GO」，**左侧被裁**（"G" 缺一竖） |

因为都贴边，**不能按画布对齐，只能按「可见区中心」对齐**。参数从原版实机
`08_牌桌_2.png` 按颜色分离量得（截图 ÷1.5 = native）：

- 蓝球直径 ≈ **73.3 native**（贴图 64 → 缩放 **×1.146**）
- 青球可见区中心 比 蓝球可见区中心 偏 **(+13.7, +1.0) native**

→ 由 `tools/make_panel_ui.py::_compose_go()` 合成 `go_btn.png` / `go_btn_dn.png`（78×78 native）。
戏里那颗**实体骰子**（`labar/骰子.png`）是 3D `Sprite3D`，不是这张合成图的一部分。

### 5b. 是 / 否 = **两块半胶囊拼一整颗**

`yes_up.png` 只有**左**圆头（右端是直切口），`no_up.png` 只有**右**圆头 —— 两张并排贴紧
才凑成一整颗「是│否」胶囊。所以：

- 先用 `AtlasTexture.region = (0,0,56,32)` **裁掉右边 8px 全透明边**（否则 STRETCH_SCALE
  会把胶囊压扁到 49/56）；
- `row` 的 `separation = 0`（贴合）；
- 显示尺寸 = 素材 **1:1（56×32 native）**。原版是否有缩放**未考证**（没找到带该提示的
  原版截图）→ 记在 §8 待办。

⚠️ 用 `KEEP_ASPECT_*` 且容器给窄时，胶囊会被**裁掉一半**（实测各剩半颗 + 直切口），
所以这里用 `STRETCH_SCALE`。

定位方式：**落点气泡**走 `_board.player_pos(my_id)` → `Camera3D.unproject_position()`
→ 控件摆到该点上方的 `lift` 处（`_sync_action_ui()`，在 `_process` 里逐帧更新）；
**GO 钮不跟角色走**，用固定屏幕锚点，见 §5e。

⚠️ `lift` 是**屏幕像素经验值**，因为角色在屏上多大取决于相机；不是 native 度量。
另外「角色头顶」还有个 `Label3D` 名字标签，气泡要抬到它上面。

**行为规则**（铁律，别动）：手上有「本次抵达的一次性机会」（`last_plot_kind != ""`）时
**不给 GO**，必须先处理掉 —— 见 `docs/decision-log.md` 的升级语义条目。

### 5c. 骰子数量选择器 = **固定 2 颗**（2026-09-26 定稿）

原版 GO 圆钮**左边缘竖排两颗骰子**：**白/亮 = 选中、灰/暗 = 未选中**。

| 项 | 结论 | 依据 |
|----|------|------|
| 颗数上限 | **2**（不是 3） | 原版实机 **5 张截图**一致：`07_牌桌` / `08_牌桌_2` / `09_牌桌_3` / `new_session_board` / `new_session_later` 全都是「上白 + 下灰」两颗，**从未出现第 3 颗** |
| 默认 | **1 颗**（第 1 颗白、第 2 颗灰） | 同上 5 张截图 |
| 骰子尺寸 | 24 native | 蓝盘可见区 h=73.3 native 里量得，骰子 bbox ≈ 24 |
| 相对蓝盘位置 | 中心偏移 `(-24.4, -12.3)` 与 `(-24.4, +13.7)` native | `08_牌桌_2.png` 像素实测 |
| 两颗都显示「1 点」 | 是**通用骰子图标**（不是点数预览） | 5 张截图里两颗恒为 1 点红心 |

→ 代码：`Sim.DICE_PER_ROLL_MAX = 2`；选择器按 `DICE_PER_ROLL_MAX` 建槽位，
点第 i 颗 = 掷 i 颗（`_set_dice_count`），掷骰时随动作一起发
（`Net.send_action("roll", [_dice_count])` → `Sim.act_roll(id, dice_count)`）。
参数同步在 `tools/make_panel_ui.py` 的 `layout.go_dice.max_count = 2`。

### 5d. 掷骰动画 / 点数展示

| 阶段 | 做法 | 素材 |
|------|------|------|
| ① 待机（GO 亮着） | 选中的骰子**缓慢翻滚**（3.5 帧/秒）；未选中的静止 1 点 + 压灰 | `dice_anim.png`（128×128 = **4×4 共 16 帧**） |
| ② 点击 → 掷出 | 骰子从 GO 钮**飞到角色头顶**，0.55 秒 ease-out，同时 26 帧/秒翻滚 + 自转 2 圈 + 放大 0.7→1.0 | 同上 |
| ③ 定格显示点数 | 1.9 秒，换成对应点数的那一面（多颗呈扇形散开） | `die_faces.png`（192×32 = **6 个骰子面**，1..6，1/4 红点） |

⚠️ `labar/anim.png` 是 **4×4=16 帧**（帧宽 32），**不是** 8×2 —— 旧记录写错了。
⚠️ `labar/骰子.png` 是 **6 个骰子面（128×64 = 3 列×2 行）**，**不是两颗骰子**。

脚本：`tools/make_panel_ui.py::_dice_faces()`。

### 5e. ⭐ GO 钮**不在角色头上**（2026-09-26 推翻旧结论）

旧记录写的是「GO 就飘在角色头上」。**错的** —— 把原版实机 **4 张**截图
（`07_牌桌` / `08_牌桌_2` / `09_牌桌_3` / `new_session_board`，都是 1536×1152
= 1024×768 ×1.5）摊开，用**青色球圆心**检测 GO 位置：

| 截图 | 角色归一化位置 | GO 球圆心归一化位置 |
|---|---|---|
| 07 / 08 / 09 | ≈ (0.498, 0.418) | **(0.691, 0.599)** |
| new_session_board（换成孙小美） | ≈ (0.498, 0.415) | **(0.691, 0.599)** |

角色站位不同、**GO 却一动不动** → 它是**固定屏幕位**，不是跟随角色的控件。

那**角色头顶那个蓝色圆盘**是什么？放大 `08_牌桌_2.png` (600,340)-(980,600) 后
可见**三个彩色方向箭头**（黄 / 蓝 / 红）→ 是**三岔路方向选择盘**（黄=直行、蓝=S 弯、
红=Z 折），**与掷骰子无关**。它=§8 里的「三岔路方向选择盘」，尚未实现。

**我们的取值**：`app.gd::GO_ANCHOR_NORM = Vector2(0.782, 0.508)` —— 老板 2026-09-26
在自己 16:9 窗口（1444×857）上标注的红框中心（`x 1077..1183, y 384..486`）。
锚的是**圆钮中心**：`_go_btn.position = anchor - _go_btn.size * 0.5`。

⚠️ 原版 4:3 帧里量到的是 `(0.691, 0.599)`，与 16:9 下的 `(0.782, 0.508)` 不同 ——
**这两套比例不可换算**（相机 fov / 宽高比都不同），所以取老板的实机标注为准。
骰子数量选择器仍然挂在球的**左边缘**（`DIE_SEL_DX/DY`，相对球左上角），随之平移。

**落点气泡（买 / 升级）仍贴角色头顶** —— 它问的是「你脚下这格」，必须跟着角色走。

## 6. 字体（已完成 ✅）

原版真字体 = `gbdata/unicode16.tft`（16px）/ `unicode24.tft`（24px），**TNFT 点阵格式**
（已破解，见 `tools/r6_tft.py`）：

```
offset 0  : "TNFT"     4B 魔数
offset 4  : u32 版本 = 1
offset 8  : u32 字高 px（16 / 24）
offset 12 : u32 = 1
offset 16 : u32 字形数 = 65536（完整 BMP）
offset 20 : 字形位图：65536 × ceil(px/8) × px 字节
            每字形 = px×px 1bpp，行主序、每行 ceil(px/8) 字节、MSB 在左，固定字框
```

校验：`unicode16 = 20 + 65536×32 = 2097172` ✓；`unicode24 = 20 + 65536×72 = 4718612` ✓。
非空字形 59223/65536（CJK 基本区 20902 全覆盖）。

已转成 BMFont 落在 `game/assets/fonts/`：`r6_16.{fnt,png}`、`r6_24.{fnt,png}`，
并在 `app.gd::_apply_ui_theme()` 里设到 `Window.theme.default_font` →
**菜单 / 大厅 / 对局的全部中文都变成原版点阵字**。

### `--uishot` 的坑（都踩过，改之前先看这段）

1. **不能按固定时刻拍**。开局头几秒角色还在「入场」状态（`me.moving != 0`），
   `_go_btn.visible` 是 **false**，3.0 秒硬拍只拍得到头上那颗骰子。
   → 现在等 `_go_btn.visible` 真为真才拍（8 秒兜底 + 警告）。
2. **`_capture()` 是协程，必须 `await` 再改游戏状态**。它内部
   `await RenderingServer.frame_post_draw` 才去 `get_viewport().get_texture()`；
   若不等它就 `Net.send_action("roll")`，角色会先动起来、下一帧把 `_go_btn.visible`
   置回 false —— **抓到的帧里按钮已经没了**（症状：诊断里 rect 正确、图里空无一物）。
3. **`_process` 本身也是协程 → `await` 期间会再起一次 `_process`**，两个并发实例
   都会往下走。2026-09-26 拍卡片二次确认框时踩到：并发的另一个实例走到 ③
   「没落到空地就再走一次」那段（`_ui_shot_last_roll` 还是 0、`_ui_shot_t > 3.0`
   立刻成立）→ 抢先掷骰 → 角色进运动态 → 确认框刚摆出来就被
   `_sync_action_entry` 判「过期」收掉，**截图永远拍不到空框**。
   → 加 `_ui_shot_confirm_active` 活动锁，并让 ③ 也看它。

⚠️ **新增 `game/assets/**` 贴图后 `--import` 要跑两次**才会被扫到
（第一次只走缓存，第二次才 `reimport`）—— 被此坑误报过 "No loader found for resource"。

| 70 | 此时不能免费 | |

`Sim.card_usable(id, card_id) -> int`：**0 = 能用**，否则返回上面某个码。
判定 = ① 这批批注 ＋ ② 每张效果在 `_apply_card` 里 `return false` 的前置条件，逐条镜像。

| 位置 | 行为 |
|------|------|
| 手牌条 | 用不了的卡**压暗**（`img.modulate = Color(0.62,0.62,0.68,0.72)`）；「锁定」的卡压得更暗 |
| 点用不了的卡 | 菜单里「使用」**置灰**（`font_disabled_color`，不然 Godot 默认字色近乎透明会整条看不见），并 toast 出原因 |
| 使用失败 | `Sim.act_use_card` 发 `card_unavailable` + `code`，UI toast `「<卡名>」用不了：<原因>` |

⚠️ **原版没有留下「卡 → 原因码」的映射表** → 上面是按批注 + 效果前置条件对出来的
**推导**，语料里只有这九条可用于此。登记为已知不确定项。

⚠️ **修复的一个静默 bug**：原本 `_apply_card` 返回 false 时**不发任何事件**
→ UI 一片死寂，这就是「点了没反应」的直接原因。现在门禁 / 效果失败都会发事件。

⚠️ **走着的时候允许用卡**（原版停留卡 9040「原地停留一次」正是边走边用的）；
只有「骰子卡正等你点步数」这个模态状态才拒绝（原因码 61）。
