# C05 · 状态互斥 —— 原版证据 vs 我们的实现

> 对齐清单 `docs/rea-2026-10-11/alignment-worklist.md` 里 **C05 原标「确定差异」**：
> 「免费、四神、睡眠、隐形等分散在多个 `effects` 字段，**可并存**」
> vs 原版「`435f80` 清除 **12 个**状态标志，再写一种状态和持续量」。
>
> 本轮用 Ghidra 12.1.4 定点反编译**验证并补全**了这条。**依据**：`435f80` 本体 +
> 它的 **16 个调用点**（脚本 `tools/ghidra_scripts/DecompileAt.java` / `FindCallers.java`）。
> 产物：`c05-status.c`（函数体）、`c05-callers.txt`（调用点带上下文指令）。

## 1. 原版机制（反编译原文）

```c
void __thiscall FUN_00435f80(void *this, uint state, byte *duration)
{
  piVar1 = (int *)((int)this + 0x118);       // 状态标志数组
  iVar2 = 0xc;                               // ← 12 个
  do {
    if (*piVar1 != 0) *piVar1 = 0;           // ← 先全部清零（这就是「互斥」）
    piVar1 = piVar1 + 1;                     // int* → 每次 +4 字节
    iVar2 = iVar2 + -1;
  } while (iVar2 != 0);
  *(undefined4 *)((int)this + state * 4 + 0x118) = 1;    // ← 再置位指定的那一个
  *(byte **)((int)this + state * 4 + 0x148) = duration;  // ← 持续量写相邻数组
  FUN_0043cb00(DAT_004fe7ac, 0x834,
      (byte *)(*(int *)((int)this + 0x38) << 8 | state), duration);   // ← 发消息
}
```

**读出来的字段布局**（对象 = 玩家/角色）：

| 偏移 | 含义 |
|---|---|
| `+0x38` | **玩家索引**（发消息时用的是它） |
| `+0x118` | **状态标志数组**，**12 个 int**（`0x118`–`0x147`） |
| `+0x148` | **状态持续量数组**，与上面**同下标**（`state*4`） |
| `+0x148` 起 | 紧跟在标志数组之后 |

**两个以前没记录的发现**：

1. **参数就是 `(state, duration)` 两个**，`state` 是 **0~11**，`duration` 是个**指针**
   （不是秒数、不是步数！说明原版的持续量是**结构化数据**，可能含类型+数值）。
2. **写入后会发消息 `0x834`**，打包方式是 `(玩家索引 << 8) | 状态号`
   —— 这应该是**给表现层/网络的同步通知**（对应我们的 `_ev("状态变化")`）。
   我们目前**没有这个通告**。

## 2. 状态号清单（从 16 个调用点反推）

调用点的机器码模式很整齐 —— **压栈顺序 `PUSH <持续量>` → `PUSH <状态号>` → `MOV ECX,对象` → `CALL`**，
所以「`CALL` 之前最后一条 `PUSH 立即数`」就是状态号：

| 状态号 | 证据地址 | 已知含义 | 依据 |
|---|---|---|---|
| `0x0` | `00420012` | ？ | — |
| `0x1` | `00420045`、`00435c61` | **无敌** | 10-11 报告：花仙子写状态 1 ✅ |
| `0x2` | `004201e6` | ？ | — |
| `0x3` | `00435a74` | **糊涂鬼（梦游）** | 报告：糊涂鬼写状态 3 ✅ |
| `0x6` | `0041f3c1`、`00431660`、`004359eb` | **小穷神** | 报告：小穷神写状态 6 ✅ |
| `0x7` | `0041f2c4`、`0043156e` | ？ | — |
| `0x8` | `0041f4cc`、`004315c9` | ？ | — |
| `0x9` | `0041f207`、`004314db`、`00435b06` | **小财神（免费）** | 报告：小财神写独立状态 9 ✅ |
| `0xb`(11) | `00420aa5` | **隐形** | 报告：隐形写状态 11 ✅ |

**没出现过的号**：`4` / `5` / `10` —— 它们不由 `435f80` 写入（可能走别的入口）。

| `FUN_004315a0` | 8 | 宠物/角色相关 |

## 3. 我们的实现（实测）

**结论：确实没对齐，而且差得比较远。**

```gdscript
# sim.gd  ~1845 起：8 个各自独立的绝对时刻字段
"invincible_until": 0.0,        # 无敌
"rest_until": 0.0,              # 挂机休息
"sleep_until": 0.0,             # 睡眠
"alien_until": 0.0,             # 外星人绑架
"invisible_until": 0.0,         # 隐形
"rush_until": 0.0,              # 暴走
"no_rent_until": 0.0,           # 小财神「免费」
"rent_pay_double_until": 0.0,   # 小穷神「双倍罚金」
```
- **没有统一写入入口**（全项目搜不到 `_set_status` / `clear_status` / `set_effect`）。
- 各字段**各自读写、互不干涉** → **可以并存**。
- 也就是说：**被小穷神附身的同时还能开花仙子**，原版**不可能**。

### 差异汇总

| 维度 | 原版 | 我们 | 影响 |
|---|---|---|---|
| 表示 | **12 个下标 + 1 个当前状态** | 8 个独立 `*_until` | 结构不同，无法表达「互斥」 |
| 写入 | **统一入口 `435f80`**，先清 12 个再置位 | 各处直接写字段 | 无单点可审查 |
| 互斥 | **天然互斥**（写一个必然清掉其余 11 个） | **可并存** | ⚠️ 玩法差异（同时中多个状态） |
| 持续量 | **结构化指针**（不是秒/步） | 绝对时刻秒 | 单位语义待进一步核 |
| 通告 | 发**消息 `0x834`**（玩家<<8 \| 状态） | 无 | 表现层/联机少一条同步 |
| 覆盖范围 | **只这 12 项互斥** | — | ⚠️ 报告明确提醒：**医院/宠物系统不一定属于这 12 项**，不能一把全混进来 |

## 4. 建议（未动手，等拍板）

**做**：照原版建一个**统一状态层**——
```gdscript
# 12 个下标，含义按上表；写入即清空其余
const STATUS_MAX := 12
func set_player_status(p: Dictionary, state: int, duration: float) -> void:
    for i in range(STATUS_MAX):
        p["status"][i] = 0
        p["status_dur"][i] = 0.0
    p["status"][state] = 1
    p["status_dur"][state] = duration
```
再把现有 8 个字段**映射**进去（`invincible→1`、`invisible→11`、`no_rent→9`、
`rent_pay_double→6`…），**保留旧字段做存档迁移**（原版对齐清单里要求「旧字段不得直接丢弃」）。

**不做**：**别把医院/酒店/宠物这些一起塞进这 12 项** —— 报告已明确说
「医院、宠物等其他系统不一定属于这 12 项」，硬塞会引入新错误。

**还缺的证据**（下一步可查）：
- `0` / `2` / `7` / `8` 四个号是什么效果 → 反编译 `FUN_00420012` 附近的 `FUN_00420100`、`FUN_004315a0`
- 持续量那个指针**指向的结构**到底是什么（含类型 + 数值？）→ 追 `+0x148` 的**读取者**
- `4` / `5` / `10` 是否存在、由谁写 → 全程序搜「写入 `+0x118 + n*4`」的其他路径
