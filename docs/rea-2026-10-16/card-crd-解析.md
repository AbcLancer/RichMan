# card.crd 完全解析（2026-10-16）

> 起因：C09 清除卡要查「范围到底几格」，报告当时说「不能立即认定清 7 格」。
> 顺着 `FUN_0041e460`（卡片表加载器）里的格式化字符串 **`"mainmenu/cardset/%s/card.crd"`**
> 找到了这张表 —— 它**不在 `gamedata.pck` 里**，而是**游戏安装目录下的外部文件**。

## 1. 位置与文件

```
F:\游戏\Rich6\mainmenu\cardset\<地图>\card.crd      ← 七张地图各一份
                               \card.txt             ← 明文卡名表（GBK，42 行）
                               \card_t.crd           ← 另一份（尺寸/内容与 card.crd 相同）
```
七张：`aiji / china / island / japan / paris / space / train`，**每份 24232 字节**。

> 早先翻 `samples/` 找不到，是因为**解包只覆盖了 `gamedata.pck`**，而 `mainmenu/` 是**磁盘上的独立目录**。

## 2. 结构（已验证）

```
偏移 0x00        文件头 40 字节（0x28）
   +0x00 = 0x65 (101)      版本？
   +0x04..0x20 = 一串 1
   +0x24 = 0x2a (42)       ★ 卡数
偏移 0x28        第 0 条记录
每条 0x240 字节（576）
   校验：40 + 42 × 576 = 24232 == 文件大小 ✅
```

### 单条记录内的字段

| 偏移 | 内容 | 证据 |
|---|---|---|
| `+0x000` | **卡序号**（1 基） | 42 张各不相同（1..42） |
| `+0x004` | **卡名**（GBK 字符串，至多 32 字节） | 如 `財神卡`（繁体） |
| `+0x024` | **卡面图路径**（GBK） | 如 `D:\work\DEMO\...\data\1_財神卡.bmp` |
| `+0x114` | 另一段中文字符串 | 卡描述/备注（待解） |
| **`+0x214`** | **内部卡 ID** | 21 种值（`-1` / `1000` / `1001` …）→ **是卡的唯一标识**，多张卡共用一个 ID 的说明它们同类 |
| `+0x218` | 布尔 | 0/1 |
| `+0x21c` | 布尔 | 0/1 |
| **`+0x220`** | **⭐ 核心参数** | **12 种值（1..100）** → 见下 |
| **`+0x224`** | **档位（1..5）** | **有规律**：步卡 = `6 - 步数`（1步卡→5、5步卡→1） |
| `+0x228` | 0 / 2 / 3 | |
| `+0x22c` | 0 / 1 / 2 | |
| `+0x230` `+0x234` `+0x238` `+0x23c` | 0..6 的小值 | 标志位组 |

⚠️ `+0x044`–`+0x20c` 那一大片是 **`0xCCCCCCCC`（MSVC 未初始化栈填充值）** 或 0 ——
**是保留区，没有内容**（拿它当参数会误判）。

**已导出**：`game/data/rules/card_table_native.json`（七张地图 × 42 张卡 × 11 个字段）。

## 3. ⭐ 对 C09 清除卡的直接结论

| 地图 | `+0x220` |
|---|---|
| 埃及 / 中国 / 海岛 / 日本 / 巴黎 / 铁路 | **7** |
| **太空** | **9** |

→ **清除卡的范围是「按地图配置」的**，六张图 7、太空 9。

**这意味着**：
- 我们 `sim.gd:3746` 的 `for step_ahead in range(1, 8)` **数字对了（7）**，
  但**来源错了** —— 它是**从卡片表读的配置值**，而不是写死的常量。
- ⚠️ **在太空地图上我们就是错的**（应该是 9）。

**而 C09 里反编译看到的那个常量 `7`**（`FUN_00428950(..., 7)`）——
结合本表看，它更像**「模式/类型」枚举**（因为 `(B << 7) | 7` 的打包方式与 C05 一致），
**真正的范围在 `card_ctx+0xc` 的 `+0x74` 字段**，那条才是从这张表读出来的值。

> ✅ 所以 C09 的判定要**修一处**：范围**不是「未知」**，而是 **`card.crd` 的 `+0x220`**
> （埃及等 6 图 = 7，太空 = 9）。

## 4. 对 C14（42 张卡门禁）的价值

`card_table_native.json` 一次性给出了**42 张卡的 11 个字段**，可以直接当 C14 的**基准表**：
- **`+0x214` 内部 ID**：同一 ID 的卡是同类（如四神的 ID 应该相同）→ 可验证「同名增强」集合
- **`+0x220`**：不同卡差异最大的字段
- **`+0x224`**：档位（步卡的 `6-步数` 规律已确认）

**待办**：把 `+0x214` 与卡名对照，**推出「ID → 卡类」映射**（报告里那张「42 卡逐项入口矩阵」
正好可以拿它来校验）。
