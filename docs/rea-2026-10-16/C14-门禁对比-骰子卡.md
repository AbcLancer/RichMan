# C14 · 门禁逐条对比（第一批：骰子卡）

> 拿 `+0x224` 的门禁函数逐个读懂，对照我们的 `card_usable()` / `_apply_card()`。

## 骰子卡 · 原版门禁 `FUN_004213c0`（150 字节）

```c
undefined4 FUN_004213c0(void *ctx, int *out_steps)
{
  if (FUN_00436230(ctx, 3) == 0) return 0;          // ① 前置
  base = ctx->[0xc]->[0x74];                         // 当前道路位置
  for (n = 1; n < 6; n++) {                          // ② ★ 只试 1..5 步
    *out_steps = n;                                  // ③ ★ 输出「合法的步数」
    target = FUN_0042bb70(base, 1);                  //    往前走 1 格
    type = target->[0x30];
    if (type == 4 || type == 0x10 || type == 7) return 1;   // ④ 特殊格 → 可用
    plot = FUN_0042bb50(target);                     //    取地块
    if (plot != 0) {
      if (plot->[0x34] == 0) return 1;               // ⑤ 无主 → 可用
      if (plot->[0x34] == ctx->[0x1c0]) {            // ⑥ 自己的
        if (plot->[0x30] == 0) return 1;             //    没建筑 → 可用
        if (FUN_0041ce40(&DAT_004ece18, plot->[0x30])) return 1;   // 建筑合法 → 可用
      }
    }
  }
  return 0;                                          // ⑦ 5 步都不行 → 不可用
}
```

### 读出来的三件事

1. **步数范围是 `1..5`**（`n < 6`）—— 不是 1..6
2. **会「试算」**：从 1 步开始逐格检查，**第一个「落点可用」的步数就返回**
3. **「落点可用」= 下列任一**：
   - 落点格子类型是 **`4` / `0x10` / `7`**（大概率是**机会格 / 商店格 / 事件格**这类特殊格）
   - 落点**地块无主**
   - 落点地块**是自己的**，且**（没建筑 / 建筑组合合法）**
   - ⚠️ **注意**：**没有**「落点不能是别人的地产」这条 —— 落在别人地上应该是允许的（会付租金）

## 我们的实现（`sim.gd:3563`）

```gdscript
"reroll":
    # 骰子卡：把「走几步」交给玩家点（UI 弹 1..6）
    p["pending_steps"] = true
    _ev("card_choose_steps", p, {"card": card_id})
```

| 维度 | 原版 | 我们 | 判定 |
|---|---|---|---|
| **可选步数** | **1..5** | UI 弹 **1..6** | ❌ **有差异**（见下） |
| **落点可用性检查** | 4 类条件 | **完全没有** | ❌ **有差异** |
| **谁决定步数** | **原版自动算**（`*out_steps`） | **玩家手选** | ❓ **语义不清，不动** |

## ⚠️ 为什么「谁决定步数」这条我不改

原版这段是**「函数自己算出合法步数并回传」**（`int *out_steps` 是**输出参数**），
**看代码不像「弹窗让玩家选」**。

但是：
- **对齐清单里 10-11 那轮明确写过**：「当前技能产生 `pending_steps`，之后手动选 1–6。
  **必须查上层选择提交顺序、载具骰数和取消耗能，窗口弹出测试不能代替入口规则**」
- 也就是说**当时的人也没定论**，同样在等更多证据
- 而且 `4213c0` 到底绑在**骰子卡**还是**小赌神技能**上，我还没排掉歧义
  （卡表里 `+0x224` 指向它，但 `421240` 那样的「技能入口」也可能调它）

**⇒ 这条留作待核，不擅自改。**

## ⚠️ 「1..5 vs 1..6」这条也暂不改（但记下来）

**原版 `n < 6` → 1..5** 是明确的。我们的 UI 是 **1..6**。
但这属于**UI 与逻辑联动**的改动（要同时改选择器上限 + 校验），
而且**得先确认「原版真的只让选 1~5」**（现在只看到门禁的试算循环，没看到 UI 层）。
**⇒ 与上一条合并，等弄清 `4213c0` 的调用者之后一起改。**

## ✅ 这条能确定的：**落点可用性检查我们完全没有**

无论「谁决定步数」，**原版都会检查落点**（特殊格 / 无主 / 自己的），
而**我们直接执行，落点在哪都走**。

**这条的差别会直接体现为玩法**：
- 原版：骰子卡**不会**把你送进「别人的高级地产」那种坑（因为它只选可用落点）
- 我们：选了就飞过去，**可能一头撞进对手的满级房**

**⇒ 这是「结构不同的地方」里最像 bug 的一条**，但**它依赖上一条的结论**
（要先知道是「玩家选」还是「系统算」才知道这条检查放在哪）。
**⇒ 一并留待下一轮。**

## 第二批：路障卡门禁 `0x421760`（线性反汇编，约 100 行）

> 这个地址**不是 Ghidra 识别的函数**（只被函数指针引用）—— 用修好的
> `DecompileAt.java` 的线性反汇编分支取到的。**顺带印证了那个修复的必要性。**

```asm
MOV EAX,[ESP+4] ; ctx
MOV EAX,[EAX+0xc]
MOV EDX,[EAX+0x74]        ; 当前道路位置
TEST EDX,EDX / SETZ CL     ; CL = (位置 == 0)   ← 一个布尔标记
MOV EDI,[EAX+0x78]
PUSH 1 / PUSH EBP
MOV ECX,EDI
CALL 0x0042bb70            ; 前进 1 格（取目标位置记录）
MOV EDI,EAX
CMP [EDI+0x34],-1          ; ★ 目标位置「业主」== -1 ?
JNZ ...                    ; 不是 -1 → 不可放
CALL 0x0042bf50            ; ★ 另一个判定（很可能「该格有没有路面道具」）
TEST EAX,EAX / JNZ ...     ; 非 0 → 不可放
CALL 0x0042bb50            ; 取地块
TEST ESI,ESI / JZ ...      ; 没地块 → 不可放
MOV EAX,[ESI+0x30]
TEST EAX,EAX / JZ ...      ; 建筑 +0x30 == 0 → 不可放
...
```

### 读出来的两件事

1. **⭐ 原版用 `-1` 表示「该格无主」**（`CMP dword ptr [EDI + 0x34], -1`），**不是 0**。
   而**能力/状态**那侧用的是 **0**（`421240` 里 `plot->[0x34] == 0` 被判为可用）——
   两处出现的值不同，说明 **`-1` 与 `0` 在原版里是两个不同的「空」**：
   很可能是**「该位置还没分配地块记录」（-1）** vs **「地块存在但还没人买」（0）**。
   > ⚠️ 我们 `plots` 里用 `owner = -1` 表示无主，**语义更接近原版的「0」那条**，
   > 所以更精确的对应关系**还要再核**（别急着照搬 `-1`）。
2. **路障要放在「有地块、有建筑、且无主」的格子上** —— 也就是**不能堵别人已有的房**。
