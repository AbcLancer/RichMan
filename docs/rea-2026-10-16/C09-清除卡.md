## 2. ⭐ 关键结论：**那个 `7` 不是格数**

**证据链**：`FUN_004289b0` 把它作为**打包参数的低位**发出去：

```c
(byte *)(*piVar1 << 7 | *puVar2)
//          ↑ B 左移 7 位   ↑ 或上 C(=7)
```

这和 **C05 的 `(玩家索引 << 8) | 状态号`** 是**同一种打包手法**：
**低位放「类型/模式」，高位放「索引」**。

→ **`7` 占的是低 7 位（0–127）→ 它是一个「模式/类型」枚举值，不是「7 格」。**
→ **而且 `FUN_00428950` 只被调用一次 → 队列里只有 1 条命令，不存在「7 条」。**

**真实的「范围」很可能在那两个字段里**（`card_ctx+0xc` 的 **`+0x74`** 与 **`+0x78`**，
相邻两字段，像是「起点 / 终点」或「位置 / 半径」）——**它们是运行时值，不是常量**。
⚠️ **这两个字段由谁写入，就是下一步要查的**（决定范围到底几格）。

**好消息**：**「逐段推进的动画队列」我们已经有**（`pending_road_clears` + 每 0.5 秒一格）
