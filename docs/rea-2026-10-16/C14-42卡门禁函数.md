## 1. 门禁函数的签名与约定（从福神卡读出）

`+0x224` 的第一个函数（福神卡 `0x420f70`，50 字节）：

```c
int FUN_00420f70(card_ctx)
{
  if (card_ctx->[0x110] > 2) return 0;              // 条件1：+0x110 必须 <= 2
  eax = card_ctx->[0xc];
  esi = eax->[0x74];                                // 位置 A
  edx = eax->[0x78];                                // 位置 B
  ret = FUN_0042bb90(B, A, 7, card_ctx);            // ★ 传 7
  if (ret < 3) return 0;                            // 条件2：返回值必须 >= 3
  return 1;                                          // 1 = 可用
}
```

**约定**：
- **签名 `int f(card_ctx)`**，**返回 1 = 可用、0 = 不可用**
- 卡片上下文里 **`+0x74` / `+0x78` 是两个位置**（`+0xc` 指向一个子结构）
- **`+0x110` 是个计数**（福神卡要求 ≤ 2）
- **又一次出现常量 `7`** —— 与 C09 清除卡的 `7` 同源（**操作/模式枚举**）

> ✅ 这**第三次**印证了 C09 的结论：**`7` 不是格数，是模式**。

## 3. 几条已经能下的结论

1. **1~5 步卡的门禁完全相同**（各 6 行、共用 `0x421240`）——
   说明**步卡的差别只在 `param`（1/10/10/10/10… 见 `C14-42卡表对齐.md`）**，
   门禁逻辑一致。**我们要不要按步数分别判可用性，是比对点。**
2. **无敌卡（26）与隐形卡（41）共用门禁 `0x421820`** —— 两卡在「可用性」上等价。
3. **衰神卡（4）直接调用穷神卡的门禁（`420fb0`）** —— 复用。
4. **汉堡卡门禁最短（19 行、不调任何函数）** —— 几乎无条件可用。
5. **飞弹卡最长（200 行）** —— 需要选目标、判范围、判建筑，逻辑最重。
