# C14 · 四神卡（财神 / 福神 / 穷神 / 衰神）门禁与效果

> 四神在报告里被点过名（「同名增强 15 种」「每张翻倍的具体字段按效果函数核对」）。
> 本文是第一批读取结果。
> **证据**：`c14-gates.c`（财神）、`card-gate-224-disasm.txt`（门禁区）

## 财神卡 —— 读得最完整

### 门禁 `FUN_0047e4e0`（**6 字节**）

```c
undefined4 FUN_0047e4e0(void) { return 1; }
```

**⭐ 永远返回 1 → 财神卡「无条件可用」**（不看位置、不看钱、不看状态）。
⚠️ 它**不在** `0x420f70`~`0x422160` 那个门禁连续区里，而是**单独放在 `0x47e4e0`**
（`.text` 末段）—— 这也是它**只有 6 字节**的原因：**直接 `mov eax,1; ret`**。

### 效果 `0x41f1a0`（线性反汇编）

```asm
MOV EAX,[ESP+4]           ; 参数
TEST EAX,EAX
MOV EBP,1                 ; ★ 默认倍率 1
JZ  ...
MOV EBP,2                 ; ★ 参数非 0 → 倍率 2（这就是「增强」）
MOV EAX,[0x00508e48]      ; 全局上限
MOV ECX,[0x00508e44]      ; 全局下限
IMUL EAX,EBP              ; 上限 × 倍率
IMUL ECX,EBP              ; 下限 × 倍率
CALL 0x00405130           ; ★ 随机（闭区间）= 金额基数
MOV ESI,EAX
PUSH 3 / MOV ECX,0x4e3b28
CALL 0x0041a950           ; 查一张表（每关系数？）
IMUL EDI,ESI              ; ★ 系数 × 随机金额
...
CALL 0x00435620           ; 取玩家 ID
CALL 0x0043ffe0           ; ★ 加钱
...
PUSH EBX（时长）
PUSH 9                    ; ★★★ 状态 9
CALL 0x00435f80           ; ★★★ 写状态 9！
```

### 读出来的三件事

1. **金额 = 随机[下限×倍率, 上限×倍率] × 查表系数**
   —— 上下限来自两个全局 `0x508e44` / `0x508e48`（应该在 Initvar 里，**可查**）
2. **增强倍率的机制确认**：`参数非 0 → EBP = 2`，**上下限同时翻倍** ✅
   （印证报告说的「同名增强」是**对字段翻倍**，不是简单加一层）
3. **⭐⭐ 财神卡会写「状态 9」** —— 而状态 9 正是 C05 里确认的「**免付租金**」。
   → **「财神卡」与「小财神技能」写的是同一个状态，效果同源** ✅
   这也**反过来印证了 C05 的状态号 9 = 免租** 是对的（两条独立证据）。

## 衰神卡 —— 直接复用穷神的门禁

```asm
00421080  ...（20 字节）
0042108a  call 0x420fb0     ; ★ 衰神门禁 = 直接调穷神门禁
0042108f  add esp,8
00421092  ret
```

**衰神卡的门禁就是「穷神卡的门禁」** —— 说明原版认为两卡**可用条件相同**
（都是「指定一个对手附身」那类），只是**附加的效果不同**。
⚠️ 所以之前 42 卡表里「衰神门禁 20 行 / 穷神 95 行」的原因就是这个转发。

## 对我们的意义

**「神卡写状态」这条值得核**：我们四神卡是**各写各的独立字段**
（`no_rent_until` / `rent_pay_double_until` / …），而**原版都是走 `435f80` 的统一状态**
——**这正是 C05 已经改掉的部分**（四神/花仙子/无敌/隐形现在都走 `set_status`）✅

`c.get("max", 50000)` 是否一致。
