## 本轮改动

1. 埃及购地后显示路侧彩色砖框与沙色地面；原版砖纹直接来自 `platform/mtlplat2.tga`。未建房的等级 0 只显示地产槽，后续建设叠加房屋模型。去掉自制业主旗和发光地基。
2. 角色单独行走时回到道路中心；原逻辑即使同格只有一人也恒定横移 `0.34` 世界单位。真实路线格点间改用四点曲线，减少弯道直线抄近路。以 `ditu.tga` 步道骨架量 94 段、每段 11 个采样点：直线中位 / 90 分位 `5.52 / 17.08 px`，曲线 `5.11 / 16.67 px`；大于 25 px 的采样点 `22 → 21`。最大误差仍约 36 px，尚有明显偏差段。
3. 建筑导出 UV 改为 `(f4,f5)`，重导 48 个模型；复核一级住宅、商店、工厂近景。一级住宅的大块屋顶草地图案已消失，三类建筑仍有局部贴图映射错误。
4. 选图菜单只列真正含 `name` 和 `tiles` 的地图 JSON，避免将格点 / UV 等辅助文件列为地图；修复 `tile_pos_of` 把数组索引误当元素查找的错误。
5. `--probe=uptown:0 --map=aiji` 现可单独拍摄刚购买、未建房的地产槽。
6. 双进程联机烟测发现原始两人状态包达到 `1428 B`，Godot 当场警告它超过本连接的 `1392 B` MTU。状态快照现先做 ZSTD 压缩（烟测实测 `1436 → 467 B`），常规包走有序不可靠通道，超出 `1200 B` 安全预算时走可靠通道，并带序号防止旧包覆盖新包。客户端校验解压长度和数据类型。修复断开服务器时重复发出断线信号的问题。

## 仍未解决，留待下一轮核对

- **逐格路侧槽位**：埃及编辑器贴图有 50 个红框，但当前地图有 94 个格点；地产槽仍按道路法线和棋盘内侧估位，部分地块可能摆在错误一侧。需要把原版 `.r6s` 的地产块、红框和 `ditu.tga` 路线进一步配准。
- **购地后的小标志**：原版画面里灰色立牌与半透明锥体究竟对应空地、建设中、特殊地块或其他状态，需要逐动作截图核实。当前只复刻已证实的彩色地产槽，尚未放这两种物体。
- **建筑 UV**：字段顺序已纠正，但 `.pol` 中的映射与图集还没完全吻合。`snap_uv_to_content()` 和边缘扩色是旧导出流程，仍需按原版建筑近景逐面核对。
- **地图与角色**：埃及地形仍是平面；其他地图仍有矩形兜底布局；棋盘角色仍是程序化小人。原版 3D 地形、角色和场景物件尚未接入。
- **联机**：本机两进程连接、开局、客户端掷骰、服务端确认和状态回传已通过；跨设备、弱网、断线重连与长局测试尚未做，不能把联机视为完全解决。
