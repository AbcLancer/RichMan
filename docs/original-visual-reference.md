## 二、渲染管线（从 `samples/gfxscript/*.gbf` 解出）

`.gbf` 是 **DirectX 8 的 effect 文件（纯文本）**，直接给出了原版的渲染方式：

```
terrgeom.gbf    地形：双贴图，ColorOp = MUL，ColorArg2 = PRIMARY
                          ↑ tex0 × tex1，且乘上顶点色(PRIMARY)
                          → 地形用「顶点色」做逐格着色，用双贴图混合光照
ui.gbf          界面：DepthTest=FALSE / AlphaTest / BlendEnable（屏幕空间绘制）
geom.gbf        普通模型：单贴图 × 顶点色
sprite.gbf      精灵：关闭光照 + AlphaTest
crystal.gbf     水晶/半透明：双 pass 正反面混合
```

**结论：地形是「一整块网格 + 顶点色 + 双贴图」，不是几百个独立地块对象。**
这正是当前工程观感不对的根因。

## 四、据此得出的表现层重做方向

1. **棋盘换成一张大平面（或轻量起伏地形）**，`albedo = ditu.tga` —— 路径、沙地、河流一次到位，不再画矩形。
2. **地块改为地面贴花**（`ditan.tga` 地毯 quad），位置取自 `*_plots_uv.json`；空置/己方/他人用染色区分。
3. **相机改为低机位斜视**，参数取 `.r6m` 头部（aiji 俯角 30°）。
4. **角色换 chibi 小模型 + 地面彩色圆盘标记 + 投影**，去掉名字悬浮标签。
5. **HUD 重排**为原版布局：顶部状态条、左下头像+2 卡片槽、右下小地图、右上玩家竖排。
6. 可选：把 `platform/model.cvd` 的建筑摆上去；天空盒用 `skybox_*`。

## 附录 B：`.r6m` 地产块表结构（2026-09-25 解出）

`offset 504` 起是地产块表，**这是把 `.r6s`/`.r6m` 的世界坐标接进棋盘坐标的唯一桥梁**。

```
offset 504   u32   n_blocks        # 街区数（埃及 20 / 中国 13 / 岛屿 8 / 日本 13 /
                                   #           巴黎 15 / 太空 26 / 火车 7 / trybuild 2）
offset 508   u32   padding = 0
offset 512   第 1 条记录开始（记录长度 = 48×A + 76）
```

单条记录的字段（`base = 该记录起始 offset`）：

| 相对偏移 | 类型 | 含义 |
|---|---|---|
| `+0`  | f32[11] | 4×4 矩阵的**前 3 行 + 第 4 行前 3 列**（缺末列 `0,0,0,1`）；含旋转基 |
| `+44` | f32[3]  | **世界平移 (x, y, z)** —— 与 `.r6s` 同名节点第 4 行一致 |
| `+56` | f32     | 恒为 `1.0`（自检用） |
| `+60` | u32     | 块序号（0 起，表内是干净的 0..n-1） |
| `+64` | u32     | **A = 宽几格** |
| `+68` | u32     | **B = 长几格** |
| `+72` | u32     | 标志位（埃及实测 3 或 1） |
| `+76` | A×B × 16 B | 每格一条 **属性**记录 = 4×u32（`0 / 655360 / 16 / 小整数`），**不含浮点坐标** |

**校验（埃及 aiji）**：Σ(48×A+76) 对 20 块 = **6032**；实测表尾 `6544`，
`512 + 6032 = 6544` ✓。A 值序列 `[5,6,6,4,4,4,6,4,5,4,6,6,6,4,3,3,4,4,5,5]`，**Σ = 94**。

**与 `.r6s` 交叉验证**：同一批 20 个街区、同序、世界平移逐个吻合（< 0.01）。
`.r6s` 名字里的 `4X3_8`（应为 5X3）、`3X3_14`/`3X3_15` 里的 `4X3_14`/`4X3_15` 重复，
是**美术命名手误**，**以 `.r6m` 表为准**。

**地板宽度**：规范《地图制作的要求》说 1 格 = 100 世界单位、地块平面宽 `A×100`、长 `B×100`。
把块矩形与棋盘坐标做相似拟合（`tools/fit_board_from_r6s.py`）反推得到 **148 世界单位/格**
（而非 100）—— 两者差 1.47 倍，**待对账**（见 `docs/decision-log.md` 议题 34）。

> 生成脚本：`tools/r6m_blocks.py`（8 张图全跑通，产物 `docs/orig-logic/<map>/r6m_blocks.{json,md}`）。
> 逐格记录器 `tools/r6s_nodes.py`（`.r6s` 一侧）。
> 对齐报告：`docs/orig-scene/aiji_fit.md`（θ=1.00°、s=0.032978、中位残差 0.73 格）。
> `offset 6588` 之后**不是路线**，是 3D 点表（40 B = 3 个 (x,y,z) + 1 标量，约 1930 点，含
> 150 个 NaN，Rg=827 / diam=8357 离群），判为轮廓/多边形点。
> **路线不在数据文件里** —— 唯一权威是 `ditu.tga` 上画出来的**步道**（见附录 C）。

## 附录 C：三张棋盘贴图到底哪张是「真身」（2026-09-25 实测，重要）

`scene/<map>/` 下有三张 1024² 的棋盘贴图，**内容并不相同**。用互相关（NCC）与
「格点 → 步道」距离两种判据实测：

| 文件 | 内容 | 与 `ditu2_1024` 的 NCC | 94 格→步道 中位距离 |
|---|---|---|---|
| **`ditu.tga`** | **游戏实际使用的棋盘贴图**：沙地 + **石子镶边的步道** + 灰色石板 + 建筑/棕榈阴影；中央是**干涸的沙质河床**（不是蓝水） | **0.089**（完全不同取景） | **0.4 px** ← **同框** |
| `ditu_noshadow.tga` | 去掉阴影/石板/水，只剩地形 + 石子步道 | 0.632（同框） | 16.2 px（❌ 不同框，别用来量对齐） |
| `ditu2_1024.tga` | 编辑器版 = `ditu_noshadow` + **蓝色水面** + **50 个红框** | 1.000（基准） | 16.2 px（❌ 同上） |

**结论**：
1. `aiji_tilepos.json` 的 `px,py` 是 **`ditu.tga` 的像素坐标** —— 看对齐、谈表现、做验收图
   只能用 `ditu.tga`；`ditu2_1024` / `ditu_noshadow` 只是**编辑器/分割用**（两者同框，
   红框坐标可比）。
2. `ditu2_1024` 的**蓝水是编辑器画的**；`ditu.tga` 里那条河是**干涸的沙质河床**，
   路线本来就从上面过 —— 据此可避免「以为路线斜穿河面」这类误判。
3. `ditu.tga` 里的**灰色石板**是一排排贴在步道两侧的浅灰矩形，疑似**地产垫层**
   （比红框更准的槽位来源），**未验证**。

### 客观对齐指标（94 格 vs `ditu.tga` 的步道掩码）—— 2026-09-25 更新

## 附录 D：⭐ 棋盘地面 UV 约定（`v` 的方向，2026-09-25 血泪）

**规则（唯一正确写法）**：

```
u = x / S + 0.5          px = (x / S + 0.5) × 1024
v = z / S + 0.5          py = (z / S + 0.5) × 1024      S = board_size = 200
```

`board_view.gd::_build_ground()` 与 `minimap.gd::_uv()` **必须同口径**。

**为什么**：Godot 的 `uv.y = 0` 在**贴图上方**（与 `Image` 第 0 行一致），
而 `ditu.tga` 上的 `py` 随 `z` 增大 → v 必须随 +z 增大。

**踩过的坑**：写成 `v = 0.5 - z/S` 会把整张贴图**沿 Z 镜像**。
因为路线是**闭合环且大致围绕棋盘中心**，「旋转 180°」与「沿 Z 镜像」在环上几乎等价
→ 症状不是明显的翻转，而是「形状对、整体错开 ≈2 格」——
这就是老板实机看到的「格子与石子路完全没对齐」的**直接原因**。

**怎么自查**：
1. 2D：`python tools/walkway_mask.py --tex ditu`（中位应 < 1 px）。
2. 小地图：`python tools/check_minimap_uv.py`（判据 C「左右环高度序」翻不了盘）。
3. 3D 终极标定：把格点像素画成十字/彩圈写进 `assets/terrain/aiji_ground.png`，
   跑 `--demo` 截图 —— 地毯必须落在标记**中心**。
   ⚠️ 改任何 `game/assets/**` 贴图后**必须** `godot --headless --path game --import`，
   否则 `.godot/imported/*.ctex` 还是旧图（骗过我们一次）。
