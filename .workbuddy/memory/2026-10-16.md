### 原版流程（反编译 4 个函数，`docs/rea-2026-10-16/C09-清除卡.md`）

  （第 4 个是 `FUN_0042bb30(A,B)` 算出来的距离）—— **只 push 了 1 条**

### ⭐ 核心结论：**`7` 不是「7 格」**

`(B << 7) | 7` —— **和 C05 的 `(玩家索引 << 8) | 状态号` 是同一种打包手法**：
低位放**类型/模式**，高位放**索引**。`7` 只占低 7 位（0–127）→ **是个模式枚举值**。
而且 `FUN_00428950` 只被调用一次 → **队列里就 1 条命令，不存在「7 条」**。

→ **报告那句「不能立即认定清 7 格」被证实是对的。**
→ 真实范围很可能在 `card_ctx+0xc` 的 **`+0x74`/`+0x78`** 两个相邻字段（运行时值）。

## 追加：四神卡门禁与效果（C14 第三批）

### ⭐ 财神卡门禁 `FUN_0047e4e0` = **6 字节，永远返回 1**

### 财神效果 `0x41f1a0`
```asm
MOV EBP,1 / MOV EBP,2      ; ★ 参数非 0 → 倍率 2（这就是「增强」）
IMUL 上限,EBP / IMUL 下限,EBP    ; ★ 上下限**同时翻倍**
CALL 0x00405130            ; 随机（闭区间）
CALL 0x0041a950            ; 查一张表（系数）
IMUL EDI,ESI               ; ★ 系数 × 随机金额
CALL 0x0043ffe0            ; ★ 加钱
PUSH 时长 / PUSH 9
CALL 0x00435f80            ; ☆☆ 写状态 9！
```
**两个收获**：
1. **「增强」的机制确认**：`EBP` 从 1 变 2，**上下限同时翻倍**
   （印证报告说的「同名增强是对字段翻倍」）
2. **☆☆ 财神卡写「状态 9」** —— 而状态 9 是 C05 确认的「免租」
   → **「财神卡」与「小财神技能」写同一个状态、效果同源**，
     也**反过来印证 C05 的状态号 9 = 免租是对的**（两条独立证据）
