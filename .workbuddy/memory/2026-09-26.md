# 2026-09-26（下午三轮）全面体检：反汇编可行性 + 未对齐清单

## 一、「全貌」的答案：不能（三条实测依据）

1. **原版没有脚本**：pck 2143 条目无 `.lua`/`.js`/字节码；唯一叫「脚本」的 `gfxscript/*.gbf`
   是**渲染着色器**。
2. **exe 里没有名称信息**：`rich6.exe`（688 KB，MSVC 2002，4 节**未加壳**）C++ 修饰名 **0**、
   RTTI `??` **0**、无 PDB/DWARF、无有用导出表。
3. **现有反汇编只能读不能追**：`rich6.asm.txt` 是**线性扫描**，无函数边界、无交叉引用。

→ 参数/文案/素材全在明文里（已全拿到），但**算法只以机器码存在**。

## 二、能做的是**定点逆向**：新建 `tools/r6_re.py` 并验证

`capstone + pefile` 自建「数据 ↔ 代码」引用索引：
`info` / `strs [-f]` / `xref <VA|off:偏移>` / `dis <VA> --n` / `calls`。

- 规模：`.text` 606 208 B → **76 098 条指令 / 1 020 个直接 call 目标（≈1500 函数）**。
- **独立复现另一个 AI 的 8 个地图函数地址 → 7/8 命中**，且调用关系吻合

## ① 传送平台「掷 1 点留在原地」—— 两个原因叠在一起

**数据**：埃及 2 格传送平台是**索引 24 / 25（路径上前后脚）**，但世界里**相隔 13.90 单位**
（正常相邻格距 ≈5）→ 路径在这里「跳」了 3 格，正是**一座传送门的两端**。

**原因 ①**：传送原来只在 `_arrive`（停下那一刻）判 → **路过不触发** → 玩家可以**停在**平台上。
**原因 ②**：`_other_platform()` 返回「第一个不是 idx 的平台格」→ 24 ↔ 25 **对称互传**。

叠加起来：玩家停在 24 → 掷 1 点走到 25（另一端）→ 被传回 24 → **看起来原地没动**。

**修法**：
- `_other_platform()` **跳过路径索引相邻**的平台格（`_tile_distance <= 1`）——
  相邻的两格就是**同一座传送门**，不是「另一处」；「传送」这件事已经体现在路径本身里了
- 传送检测移到 `_advance` 的**逐格循环**（**经过即传送**），传送后 `moving = 0`
- 新标记 `p["_teleported"]`：同一段行走内不再传（防 A→B→A 死循环），`_arrive` 之后复位
- `_resolve_event` 的 platform 分支退化为兜底

顶部深色条**只显示点券数字**「50」。我们在 95×30 的槽位里塞了「卡面 + 文字」→
卡面把文字压住 = 老板说的「看不清」。 → 改成纯文字、居中、字 13 native。

## ② 精灵屋**只有一张面板**（老板的质疑是对的）

原版屏幕上只有「小神仙商店」一块；我上轮把「持有栏 + 商店」并排是**错的**（虽然两张
256² 底图确实是一对，但一次只显示一张）。→ 去掉持有栏。

**那持有小神仙显示在哪？** 原版 `使用卡片.png` 给出答案：**左下角角色面板右边**
（「钱夫人」右侧就是「小财神」）。→ 新增 `_pet_strip`（角色面板右侧横排，最多 5 只，
用 `assets/pets/<id>/01..04.png` 小头像）。

## ③ 确认框底图找到了：`uitex/other/infobk.tga`

原版是**灰白圆角 + 蓝底边**的独立对话框（文案 = Info 203 原文）。
→ 入库 `infobk.png`，用 `StyleBoxTexture` 九宫格做 `_pop` 底，文字改深色。
顺带入库 `saybk.tga`（台词气泡）/ `msgbox.tga` / `hint.tga`。

## ④ 卡片菜单 = 「锁定 / 使用 / 喂食」（**没有「丢弃」**）
